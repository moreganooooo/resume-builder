# dashboard/ (Go module)

- `dashboard/` is a native Go module leveraging the Charmbracelet ecosystem (Bubble Tea v2, Lip Gloss v2, Glamour Markdown, Harmonica physics, and Huh forms, launched via `resume dashboard`).
  - Pre-compilation: `scripts/dashboard.py` and `scripts/charm_prompt.py` dynamically compile their Go binaries (`dashboard/bin/dashboard` and `dashboard/bin/prompt`) on first launch for sub-millisecond execution (gitignored - never committed). They gracefully fall back to slow `go run` or Questionary prompts if Go is unavailable.
  - Interactive Screens: Includes Pipeline checkpoint tracker, Jobs accordion browser, Application Answers chat (with Python-owned persistence and grounding checks), Knowledge Base Explorer (`viewKB` for browsing tools, metrics, facts, and projects with Glamour-rendered markdown viewports and live substring filtering), Progress monitor with Bubbles progress bars, and Report view.
  - Application Answers keeps model-written text on the job until the user explicitly finalizes it. EEO handling and grounding validation happen in `scripts/application_answers.py`; the dashboard is presentation and subprocess orchestration only.
  - Harmonica Physics & Responsive Viewport: Smooth spring-eased reveal animations and automatic terminal resize reflow with 80x24 minimum viewport warning cards.
  - **Visual TUI Inspection**: Generate high-DPI retina snapshots with `python3 scripts/capture_tui_visuals.py --out artifacts/tui_capture.png`. Claude can read/view `artifacts/tui_capture.png` directly to visually audit terminal layout, alignment, and color contrast.
  - **VHS Recordings**: Tapes located in `dashboard/tapes/` (`menu`, `help`, `light` (Catppuccin Latte via `dashboard.py --theme`), `cli_menu` (Python CLI menu), `cli_find_jobs`, `cli_build_documents`, `cli_bullet_bank`, `cli_drop_knowledge`, `cli_settings`, `cli_help` (CLI submenus; Command Center just opens the dashboard, so it has no tape), `pipeline`, `pipeline_help`, `pipeline_board` (`v` cycles grouped -> flat -> board, so the board is two presses from the default, not one), `progress`, `progress_help`, `insights` (the other half of Progress; menu slot 3), `heatmap` (Insights; the Mission Control duplicate on Progress was removed), `jobs`, `jobs_help`, `jobs_search`, `jobs_filter` (workplace = Remote), `matrix`, `kb_view`, `kb_tools`, `kb_metrics`, `kb_facts`, `kb_projects`, `kb_skills` -- the KB screen has no `?` overlay, `answers`, `mobile`; the dashboard's Documents entry has no tape of its own because it suspends into the Python Build Documents submenu, which `cli_build_documents` already records -- a second tape would capture the same screen through a different door.

**A tape types menu POSITIONS, so inserting a menu item breaks every tape below it.** `NewMenuModel`'s list (`internal/ui/menu/list.go`) is the source of truth: 1 Pipeline, 2 Progress, 3 Insights, 4 Jobs, 5 Documents, 6 Knowledge Base. Adding "Insights" at slot 3 shifted Jobs 3->4, Documents 4->5 and the KB 5->6, and ten tapes went on typing the old numbers -- the five `jobs*`/`matrix` tapes opened Insights and the five `kb_*` tapes opened Jobs, each then burning its full `Wait+Screen` timeout on text that would never appear (fixed 2026-09-22). The `Wait+Screen@30s /SCREEN NAME/` guard after every menu keypress is what keeps this a timeout rather than a silently-wrong screenshot; keep it on any new tape, and re-run the affected tapes after touching that list rather than assuming. run all via `scripts/capture_tui_visuals.py`, which writes `artifacts/tui_*.png|gif`. `answers` makes one real Gemini call) record animated GIFs via `vhs <tape_path>`.
  - **Android & Mobile Termux**: Termux (`TERMUX_VERSION`) and mobile mode (`RESUME_BUILDER_MOBILE=1`) are auto-detected, relaxing minimum terminal dimensions to 35x12 and enabling full touch/tap navigation via `tea.WithMouseCellMotion()`. Run `./scripts/build_mobile.sh` to cross-compile static ARM64/AMD64 binaries into `dist/mobile/`. Slash commands `/visual-tui`, `/build-mobile`, and `/audit-tui` are available in `.claude/commands/`.
- **`dashboard/` was vendored from the `career-ops` sibling repo's
  `dashboard/` on 2026-07-22** (themed to this project's palette/icons,
  plus two real bugs fixed there — a tracker-column-count mismatch and a
  narrow-terminal crash). This repo's copy is authoritative going
  forward; `career-ops/dashboard/` is not where future dashboard changes
  should land, and may drift stale over time. See `docs/IDEAS_ARCHIVE.md`
  for the full writeup.
- **The binary's CLI is Cobra + fang (`main.go`, `cli.go`), not stdlib `flag`.** Flags are `--double-dash`; single-dash long names (`-profile`) are promoted before parsing so old invocations keep working. `--help`, `--version` and errors use the design system's CLI palette (`guidelines/cli-fang.card.html`: Mauve program, Blue headings, Peach flags, Subtext descriptions) and errors render "✗ Error …" plus a named fix (`fixError`). `--no-color` sets `NO_COLOR` before fang builds its writer.
- **The resume-builder Glamour style is the design system's JSON, embedded** (`internal/theme/glamour-resumebuilder.json`, a copy of `docs/DesignSystem/assets/glamour-resumebuilder.json`; `TestGlamourJSONMatchesDesignSystem` fails on drift -- recopy, don't edit the copy). Only the document margin is overridden (to 0, for viewer.go's exact-width wrap). Catppuccin themes keep the palette-derived Go style.
- **Long-running actions show `ElapsedTimer` (`screens/elapsedtimer.go`, over `bubbles/stopwatch`)**: spinner, label, m:ss, "(esc to cancel)", and a Yellow overrun line past the usual duration. It replaced the old stalled hint.
