If by “this app” you mean the built-in Resume Builder actions available in ChatGPT, there are currently three main capabilities:
1. Parse a Resume
   * Upload a resume file (PDF, DOCX, etc.).
   * The tool extracts and structures the content into sections like work experience, education, skills, certifications, and more.
   * This creates a parsed version that other actions can work with.
2. Diagnose / Analyze a Resume
   * Reviews the parsed resume.
   * Provides feedback on strengths, weaknesses, formatting, content quality, and areas for improvement.
   * Useful for getting an objective assessment before applying to jobs.
3. Update a Resume
   * Makes targeted edits to an already parsed resume.
   * Can update bullet points, add skills, revise summaries, modify job descriptions, add certifications, and similar changes.
   * Designed for tailoring a resume to specific roles or improving existing content.
For example, you could:
* Upload your resume.
* Ask for a diagnosis and scoring.
* Then say, “Tailor this for a CRM Marketing Manager role,” and the update action can revise the content accordingly.

A few interesting things jump out:
1. You're looking at an MCP-based tool integration
 The references to:
* parser_resume
* diagnose_resume
* update_resume
...are action definitions exposed through an MCP (Model Context Protocol) server. The clues are:
* mcp.jobright.ai
* parser-resume-mcp.html
* diagnose-resume-mcp.html
That strongly suggests this isn't an OpenAI-built resume engine. It's likely a service provided by a company called Jobright and exposed to ChatGPT through MCP.
In other words:
ChatGPT = interface
 ➡️
MCP server (Jobright) = actual resume service
 ➡️
Resume analysis/generation logic = running on Jobright's servers
________________


2. "Visibility: public" does NOT mean open source
 This trips up a lot of people.
In MCP land, "public" generally means:
The action schema is visible and callable.
It does not mean:
The source code is public.
Think of it like seeing the API documentation for a service without seeing the code behind it.
You can see:
{
 "fileId": "12345"
}
but not the code that actually scores resumes.
________________


3. The schemas themselves are public
 The action definitions are effectively API contracts.
For example:
{
 "fileId": "uuid-from-parser",
 "items": [
   {
     "indexPath": "summary",
     "action": "update",
     "value": "..."
   }
 ]
}
This tells us a lot about the architecture:
* Resume is parsed into structured JSON
* Updates are applied as patches
* Resume sections have paths
* The service stores an editable intermediate representation
This is actually a pretty elegant design.
________________


4. Could you install this exact thing locally?
 Probably not.
Based on what you've shown:
* The UI widgets live at mcp.jobright.ai
* The APIs appear to live at swan-api.jobright.ai
* The analysis logic is server-side
Unless Jobright has released the source code somewhere, there is probably nothing available to download and run locally.

5. Could you build something very similar locally?
 Absolutely.
The architecture would look something like:
Resume PDF

   ↓

   ↓

Feedback + Score
   ↓

Most of the pieces already exist:

* Resume extraction → LLMs
* Resume scoring → custom prompts/rules

* PDF generation → HTML/CSS → PDF
Honestly, if I were building a resume tool today, I'd probably use:
* Python

* OpenAI API or local model
* JSON schema for resume structure
* WeasyPrint or ReportLab for PDF generation
